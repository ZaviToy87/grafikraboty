## ✅ ЧТО ИСПРАВЛЕНО

### 1. **Закрытие смены — фактическое сохранение**

**Проблема:** Кнопка "Закрыть смену" работала, но смена не закрывалась фактически — запись в БД создавалась, но статус не обновлялся.

**Причины:**
1. Фронтенд отправляет `revenue_total`, а бэкенд ожидал `closing_sum`
2. Роут `/<shift_id>/close` не обновлял поле `notes` в таблице `schedule`

**Исправление:**
```python
# web_work_journal.py строка 312
closing_sum = float(data.get('closing_sum', data.get('revenue_total', 0) or 0))
notes = data.get('notes', data.get('close_note', ''))

# Строка 335-339
# Обновляем смену - помечаем как закрытую
cursor.execute('''
    UPDATE schedule
    SET notes = COALESCE(notes, '') || ' | Закрыта: ' || ?
    WHERE id = ?
''', (notes, shift_id))
```

**Файл:** `web_work_journal.py` (строки 307-341)

### **API роуты рабочего журнала:**

| Роут | Метод | Описание |
|------|-------|----------|
| `/api/work-journal` | GET | Список смен |
| `/api/work-journal/open` | POST | Открыть смену |
| `/api/work-journal/entry` | POST | Добавить запись |

| `/api/work-journal/shift/<id>` | DELETE | Удалить смену |

### **Структура БД:**

```sql
-- Таблица смен
CREATE TABLE schedule (
    id INTEGER PRIMARY KEY,
    user_id INTEGER,
    year INTEGER,
    month INTEGER,
    day INTEGER,
    task_ids TEXT,
    notes TEXT,  -- ← Сюда пишется " | Закрыта: ..."
    created_at TIMESTAMP,
    updated_at TIMESTAMP
);

-- Таблица записей журнала
CREATE TABLE work_journal_entries (
    id INTEGER PRIMARY KEY,
    shift_id INTEGER,
    user_id INTEGER,
    kind TEXT,  -- 'opening' или 'closing'
    amount REAL,
    note TEXT,
    created_at TIMESTAMP
);
```
