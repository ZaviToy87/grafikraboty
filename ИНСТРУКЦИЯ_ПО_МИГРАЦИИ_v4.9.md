## 📊 НОВАЯ СТРУКТУРА БД

### work_schedule (планируемый график)
```sql
CREATE TABLE work_schedule (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id INTEGER NOT NULL,
    year INTEGER NOT NULL,
    month INTEGER NOT NULL,
    day INTEGER NOT NULL,
    task_ids TEXT DEFAULT '[]',
    notes TEXT,
    created_at TIMESTAMP,
    updated_at TIMESTAMP,
    FOREIGN KEY (user_id) REFERENCES users(id),
    UNIQUE(user_id, year, month, day)
);
```

**Назначение:** Кто должен работать по плану

### work_sessions (фактические смены)
```sql
CREATE TABLE work_sessions (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id INTEGER NOT NULL,
    work_schedule_id INTEGER,  -- Связь с графиком (может быть NULL)
    year INTEGER NOT NULL,
    month INTEGER NOT NULL,
    day INTEGER NOT NULL,
    opened_at TIMESTAMP,
    closed_at TIMESTAMP,
    opening_sum REAL DEFAULT 0,
    closing_sum REAL DEFAULT 0,
    revenue_total REAL DEFAULT 0,
    acquiring_amount REAL DEFAULT 0,
    evening_cash REAL DEFAULT 0,
    evening_cashless REAL DEFAULT 0,
    notes TEXT,
    status TEXT DEFAULT 'opened',  -- 'opened' | 'closed'
    created_at TIMESTAMP,
    updated_at TIMESTAMP,
    FOREIGN KEY (user_id) REFERENCES users(id),
    FOREIGN KEY (work_schedule_id) REFERENCES work_schedule(id)
);
```

**Назначение:** Кто реально работал (открыл/закрыл смену)

### work_journal_entries (записи журнала)
```sql
CREATE TABLE work_journal_entries (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    shift_id INTEGER NOT NULL,  -- Ссылка на work_sessions
    kind TEXT NOT NULL,  -- 'opening' | 'closing' | 'sale' | 'expense'
    amount REAL,
    note TEXT,
    created_at TIMESTAMP,
    user_id INTEGER,
    FOREIGN KEY (shift_id) REFERENCES work_sessions(id),
    FOREIGN KEY (user_id) REFERENCES users(id)
);
```

**Назначение:** Записи об операциях в смене

## 🐛 ВОЗМОЖНЫЕ ПРОБЛЕМЫ

### Ошибка "table schedule not found"
**Решение:** Таблица переименована в `work_schedule`. Обновите код.

### Ошибка "shift_id is null"
**Решение:** Проверьте, что миграция `work_journal_entries` прошла успешно.

### Смены не отображаются
**Решение:** Проверьте, что `work_sessions` содержит данные:
```sql
SELECT * FROM work_sessions LIMIT 10;
```

### Ошибка API 404
**Решение:** Проверьте, что `web_work_journal.py` обновлён и зарегистрирован в `web_server.py`
