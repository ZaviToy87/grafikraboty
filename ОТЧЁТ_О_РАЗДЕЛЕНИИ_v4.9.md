## 🎯 ЦЕЛЬ

Разделить понятия **"график работы"** и **"рабочая смена"**:

- **График (work_schedule)** — планируемое расписание (кто ДОЛЖЕН работать)
- **Смена (work_sessions)** — фактически отработанное время (кто РЕАЛЬНО работал)

**Ключевое требование:**
- ✅ Сотрудник САМ открывает/закрывает смену
- ✅ Удаление смены НЕ влияет на график
- ✅ График и смены — полностью независимые сущности

## 🔄 МИГРАЦИЯ ДАННЫХ

### Этапы миграции:

**1. Переименование `schedule` → `work_schedule`**
```sql
ALTER TABLE schedule RENAME TO work_schedule;
```

**2. Создание `work_sessions`**
```sql
CREATE TABLE work_sessions (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id INTEGER NOT NULL,
    work_schedule_id INTEGER,  -- Связь с графиком
    year INTEGER NOT NULL,
    month INTEGER NOT NULL,
    day INTEGER NOT NULL,
    opened_at TIMESTAMP,
    closed_at TIMESTAMP,
    opening_sum REAL DEFAULT 0,
    closing_sum REAL DEFAULT 0,
    revenue_total REAL DEFAULT 0,
    acquiring_amount REAL DEFAULT 0,
    evening_cash REAL DEFAULT 0,
    evening_cashless REAL DEFAULT 0,
    notes TEXT,
    status TEXT DEFAULT 'opened',
    created_at TIMESTAMP,
    updated_at TIMESTAMP,
    FOREIGN KEY (user_id) REFERENCES users(id),
    FOREIGN KEY (work_schedule_id) REFERENCES work_schedule(id)
);
```

**3. Миграция существующих смен**
- Найти все записи в `work_schedule` с `task_ids LIKE '%6%'`
- Создать соответствующие записи в `work_sessions`
- Перенести суммы из `work_journal_entries`
- Сохранить связь через `work_schedule_id`

**4. Обновление `work_journal_entries`**
- Изменить связь: `shift_id` → ссылается на `work_sessions.id`
- Перенести данные без потерь

## 🔧 API ENDPOINTS (обновлённые)

### GET /api/work-journal/
Получить список смен за месяц

**Параметры:**
- `year` (int) — год
- `month` (int) — месяц
- `user_id` (int, опционально) — ID сотрудника

**Ответ:**
```json
{
  "status": "success",
  "sessions": [
    {
      "id": 123,
      "user_id": 2,
      "work_schedule_id": 456,
      "year": 2026,
      "month": 3,
      "day": 23,
      "opened_at": "2026-03-23T09:00:00",
      "closed_at": null,
      "opening_sum": 15000,
      "closing_sum": 0,
      "status": "opened",
      "full_name": "Валерия Сотрудник",
      "is_open": true,
      "is_closed": false
    }
  ]
}
```

### POST /api/work-journal/open
Открыть смену

**Тело запроса:**
```json
{
  "year": 2026,
  "month": 3,
  "day": 23,
  "morning_cash": 15000
}
```

**Ответ:**
```json
{
  "status": "success",
  "message": "Смена открыта",
  "session_id": 123
}
```

### POST /api/work-journal/entry
Добавить запись в журнал

**Тело запроса:**
```json
{
  "shift_id": 123,
  "amount": 5000,
  "entry_type": "sale",
  "description": "Продажа товара"
}
```

### POST /api/work-journal/close
Закрыть смену

**Тело запроса:**
```json
{
  "shift_id": 123,
  "closing_sum": 20000,
  "revenue_total": 25000,
  "acquiring_amount": 5000,
  "evening_cash": 15000,
  "evening_cashless": 10000,
  "notes": "Смена закрыта"
}
```

### DELETE /api/work-journal/shift/<id>
Удалить смену (только админ)

**Важно:** Удаляет только смену из `work_sessions`, график (`work_schedule`) НЕ изменяется!

##  ИЗМЕНЕНИЯ В КОДЕ

### web_work_journal.py

**Старая версия:**
```python
# Получение смен из schedule
cursor.execute('''
    SELECT s.id, s.user_id, s.year, s.month, s.day, ...
    FROM schedule s
    WHERE s.year = ? AND s.month = ?
    AND (s.task_ids LIKE '%6%' ...)
''', (year, month))
```

**Новая версия:**
```python
# Получение смен из work_sessions
cursor.execute('''
    SELECT ws.id, ws.user_id, ws.year, ws.month, ws.day,
           ws.opened_at, ws.closed_at, ws.opening_sum, ...
    FROM work_sessions ws
    JOIN users u ON ws.user_id = u.id
    WHERE ws.year = ? AND ws.month = ?
''', (year, month))
```

## 🎯 СЦЕНАРИИ ИСПОЛЬЗОВАНИЯ

### Сценарий 1: Сотрудник открывает смену по графику

1. Сотрудник заходит в "Рабочий журнал"
2. Видит свой график на сегодня (из `work_schedule`)
3. Нажимает "📦 Открыть смену"
4. Вводит сумму утренней кассы
5. ✅ Создаётся запись в `work_sessions`
6. ✅ Статус: "🟢 Открыта"

### Сценарий 2: Сотрудник открывает смену вне графика

1. Сотрудник заходит в "Рабочий журнал"
2. Нажимает "📦 Открыть смену" (графика нет)
3. Вводит сумму утренней кассы
4. ✅ Создаётся запись в `work_sessions`
5. ✅ `work_schedule_id = NULL` (вне графика)
6. ✅ Статус: "🟢 Открыта"

### Сценарий 3: Админ удаляет смену

1. Админ видит смену в списке
2. Нажимает "🗑️ Удалить смену"
3. ✅ Удаляется запись из `work_sessions`
4. ✅ Удаляются записи из `work_journal_entries`
5. ✅ Запись в `work_schedule` остаётся (график не изменён)

### Сценарий 4: Сотрудник закрывает смену

1. Сотрудник нажимает "🌙 Закрыть смену"
2. Вводит суммы: наличные, безнал, эквайринг
3. ✅ Обновляется `work_sessions.status = 'closed'`
4. ✅ Создаётся запись в `work_journal_entries` (kind='closing')
5. ✅ Статус: "✅ Закрыта"
