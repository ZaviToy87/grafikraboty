## 🐛 ОПИСАНИЕ ПРОБЛЕМЫ

На скриншоте пользователя видно, что в интерфейсе рабочего журнала отображается **двойной интерфейс**:

1. **Верхний блок** (основная смена):
   - "23.3.2026 · Валерия Сотрудник 🟢 Открыта"
   - Статус: "Открыта"
   - Кнопки: "Подробнее", "➕ Запись", "Закрыть смену"

2. **Внутренний блок** (детальный просмотр):
   - "Смена за 23.3.2026 · Валерия Сотрудник"
   - Статус: "⚪ НЕ ОТКРЫТА" ← **НЕПРАВИЛЬНО!**
   - Кнопка: "📦 Открыть смену" ← **ЛИШНЯЯ!**

Это создаёт путаницу: смена уже открыта, но в детальном просмотре показывается как "не открытая" с кнопкой "Открыть смену".

---

## 🔍 ПРИЧИНЫ ПРОБЛЕМЫ

### 1. Неправильное определение статуса смены в JS

**Было:**
```javascript
const isClosed = s.is_closed || s.closed_at;
const isOpen = s.is_open || (!isClosed && openingEntry);
```

**Проблема:**
- `s.is_closed` и `s.is_open` могут приходить как `True/False` (Python boolean)
- Проверка `||` не работает корректно с булевыми значениями из JSON
- `openingEntry` определяется через `entries.find()`, но сравнение было нестрогим

### 2. Кнопка "Открыть смену" показывалась всегда

**Было:**
```javascript
${openingEntry ? '' : `<button...>Открыть смену</button>`}
```

**Проблема:**
- Проверка работала, но `openingEntry` мог быть `undefined` вместо `null`
- Не было явной переменной для контроля отображения

## ✅ ВНЕСЁННЫЕ ИСПРАВЛЕНИЯ

### 1. Исправлено определение статуса смены (app.js, строки 2990-2992)

```javascript
// Статус смены - используем данные с сервера в первую очередь
const isClosed = s.is_closed === true || s.closed_at || closingEntry !== undefined;
const isOpen = s.is_open === true || (!isClosed && openingEntry !== undefined);
```

**Что исправлено:**
- Явное сравнение `=== true` для булевых значений
- Проверка `!== undefined` для записей
- Приоритет данным с сервера (`s.is_open`, `s.is_closed`)

### 2. Улучшено отображение статусного бейджа (строки 2994-2996)

```javascript
const statusBadge = isClosed
    ? '<span class="badge" style="background:#10b981; color:white; padding:4px 10px; border-radius:6px; font-size:12px;">✅ Закрыта</span>'
    : (isOpen ? '<span class="badge" style="background:#f59e0b; color:white; padding:4px 10px; border-radius:6px; font-size:12px;">🟢 Открыта</span>' 
              : '<span class="badge" style="background:#6b7280; color:white; padding:4px 10px; border-radius:6px; font-size:12px;">⚪ Не открыта</span>');
```

**Что исправлено:**
- Добавлены явные inline-стили для надёжности
- Убраны классы `badge-success/warning/secondary` (могут не загрузиться)

### 3. Исправлена логика кнопки "Открыть смену" (строки 3070-3078)

```javascript
// Кнопка "Открыть смену" показывается ТОЛЬКО если смена ещё не открыта
const showOpenButton = !openingEntry;
actionButtons = `
    <div class="action-buttons" style="display:flex; flex-wrap:wrap; gap:8px; margin-top:12px;">
        ${showOpenButton ? `<button...>📦 Открыть смену</button>` : ''}
        ${openingEntry && !closingEntry ? `<button...>🌙 Закрыть смену</button>` : ''}
        <button...>➕ Добавить запись</button>
    </div>
`;
```

**Что исправлено:**
- Добавлена явная переменная `showOpenButton`
- Добавлен `margin-top:12px` для отступа
- Кнопка "Открыть смену" теперь показывается **только** если нет записи об открытии

## 🔧 ТЕХНИЧЕСКИЕ ДЕТАЛИ

### Логика определения статуса смены:

**Сервер (Python, web_work_journal.py):**
```python
# GET /api/work-journal
is_open = row['opening_count'] > 0 and row['closing_count'] == 0
is_closed = row['closing_count'] > 0

# GET /api/work-journal/shift/<id>
opening_entry = next((e for e in entries if e['kind'] == 'opening'), None)
closing_entry = next((e for e in entries if e['kind'] == 'closing'), None)
shift['is_open'] = opening_entry is not None and closing_entry is None
shift['is_closed'] = closing_entry is not None
```

**Клиент (JavaScript, app.js):**
```javascript
// После исправления
const isClosed = s.is_closed === true || s.closed_at || closingEntry !== undefined;
const isOpen = s.is_open === true || (!isClosed && openingEntry !== undefined);
```

### Разделение данных:

- **schedule** — планируемый график работ (записи с task_id=6 "Смена физическая")
- **work_journal_entries** — фактические записи об открытии/закрытии/продажах

**Важно:** Удаление смены НЕ влияет на график!
